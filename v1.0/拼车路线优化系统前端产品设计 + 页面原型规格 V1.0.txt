# 拼车路线优化系统前端产品设计 + 页面原型规格 V1.0

文档性质：

> 面向产品经理、UI设计师、前端工程师的产品设计规格。

基于：

- 《拼车路线优化系统业务需求规格 V1.0》
- 《拼车路线优化系统技术方案设计 V1.0》
- 《数据库设计 + API接口设计 V1.0》

设计目标：

让用户能够：

1. 快速创建拼车任务
2. 上传/录入乘客信息
3. 查看系统优化过程
4. 理解最终拼车方案
5. 查看路线、费用、分摊
6. 分享给司机或乘客

---

# 一、产品定位

## 产品名称（暂定）

拼车路线优化助手


## 核心用户

### 用户A：组织者

例如：

- 公司员工通勤负责人
- 活动负责人
- 旅游组织者
- 学校接送负责人


主要需求：

> 我要30个人拼车，系统帮我自动分组并降低费用。


---

### 用户B：司机

需求：

> 我只想知道我这一车接谁、怎么走。


---

### 用户C：乘客

需求：

> 我坐哪辆车？多少钱？几点到？


---

# 十五、费用展示设计


避免用户误解。


不要显示：

“车费”


显示：

## 预计费用


例如：

```
车辆费用:

100元


3人均摊:

33.33元/人


说明:

实际支付以承运平台为准

```


---

# 十六、异常展示设计


不要显示：

技术错误。


例如：

错误：

```
DIRECT_TIMEOUT
```


用户看到：

```
⚠ 张三无法加入方案


原因：

从当前位置到目的地
预计驾驶时间超过90分钟


建议：

调整目的地或单独安排车辆

```
