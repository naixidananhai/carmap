# 拼车路线优化系统数据库设计 + API接口设计 V1.0

文档性质：

> 面向后端开发、数据库工程师、前端开发的系统设计文档。

目标：

建立一个支持：

- 拼车任务创建
- 地理数据管理
- 地图矩阵缓存
- 候选路线存储
- 优化任务执行
- 方案版本管理
- 结果展示
- 历史查询

的完整数据体系。

---

# 一、系统总体架构

整体数据流：

```
用户创建拼车任务

        |
        ↓

任务数据库

        |
        ↓

地图数据服务

        |
        ↓

距离时间矩阵缓存

        |
        ↓

算法优化服务

        |
        ↓

方案数据库

        |
        ↓

前端展示/API
```


---

# 二、数据库设计原则

## 1. 数据库选型

推荐：

### 主数据库

MySQL 8.0

负责：

- 用户数据
- 拼车任务
- 人员信息
- 方案结果


---

### 缓存数据库

Redis

负责：

- 地图矩阵缓存
- 优化中间状态
- 任务进度


---

### 文件存储

对象存储：

例如：

- OSS
- MinIO


负责：

- 地图路线 polyline
- 导出文件
- 报表

# 五、API接口设计


接口风格：

RESTful。


统一：

```
/api/v1
```


---

# 六、任务创建接口


## POST

```
/carpool/tasks
```


创建拼车任务。


请求：

```json
{
"name":"广州机场拼车",

"destination":{
"name":"机场",
"lng":113.3,
"lat":23.4
},

"optimization_mode":"cost",

"passengers":[

{
"id":"001",
"name":"张三",
"lng":113.1,
"lat":23.2
}

]
}
```


返回：

```json
{
"task_id":10001,

"status":"CREATED"
}
```


---

# 七、启动优化接口


## POST


```
/carpool/tasks/{id}/optimize
```


请求：

```json
{
"budget":300
}
```


返回：

```json
{
"job_id":888,

"status":"RUNNING"
}
```


---

# 八、查询优化状态
